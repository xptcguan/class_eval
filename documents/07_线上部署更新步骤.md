> 2. 榜单快速切换周期的渲染报错

## 第一步：建一个能登录的管理员账号（3 分钟）

### 为什么你之前登录不了

你插的那条 SQL 用的是 **bcrypt** 哈希：

```
$2b$12$EixZaYb7QH0GpRcJ/.R6X.6O2gH1Y8X6J0Y0gH1Y8X6J0Y0gH1Y8X6J
```

本系统**不用 bcrypt**，用的是标准库的 **PBKDF2**，格式是这样：

```
pbkdf2_sha256$200000$盐的hex$摘要的hex
```

两者算法不同、格式也不同。`verify_password()` 拿到 `$2b$12$...` 会直接判失败，
所以不管你输什么密码，都提示"账号或密码错误"。

### 正确做法：用下面这条 INSERT

我已经按你的密码算好了哈希（本地端到端验证过能登录）。

**操作**：Supabase → SQL Editor → New query → 全文粘贴 → Run

```sql
-- 若已存在同账号，先删掉（只动 teachers 表这一行）
delete from public.teachers where username = 'admin';

insert into public.teachers
    (id, username, password_hash, display_name, role, is_active, must_change_pwd)
values
    ('0468e660-c2e4-45d8-a99d-aba1eb8771b4',
     'admin',
     'pbkdf2_sha256$200000$d0f740b39fd6e4653e6d488f0134c376$b3b0b27b1e83f789cccb72af3af701bcc6a9185d62f2771a1b08c38ba1209839',
     '系统管理员',
     'head_teacher',
     true,
     false);

-- 验证：应返回 1 行，is_active = true
select id, username, display_name, role, is_active
from public.teachers
where username = 'admin';
```

**登录信息**

| 项 | 值 |
|---|---|
| 账号 | `admin` |
| 密码 | `teacher2026` |
| 身份 | 班主任（可建班、可管理全部） |

> 想换密码：不要手写哈希。最省事的办法是登录后到「设置与导出 → 账号安全」改。
> 或者在本地跑 `python -c "from core.security import hash_password; print(hash_password('你的新密码'))"`，
> 把输出贴进 `password_hash` 字段。

### 如果 `role` 或 `is_active` 报类型错误

说明你的表是照 `sql/schema_sqlite.sql` 建的（布尔列成了 integer）。
把 `true` 改成 `1`、`false` 改成 `0` 即可，或者干脆先跑第二步的规范化脚本。

## 第二步：修表结构 + 重启（5 分钟）

### 2.1 先看当前类型（只查不改）

Supabase → SQL Editor → 执行 `sql/check_bool_types.sql`：

```sql
select table_name, column_name, data_type
from information_schema.columns
where table_schema = 'public'
  and column_name in ('is_active', 'is_archived', 'show_rank', 'must_change_pwd')
order by table_name, column_name;
```

| 结果 | 说明 | 下一步 |
|---|---|---|
| 全是 `boolean` | 表建对了 | 跳过 2.2，直接 2.3 |
| 有 `integer` | 当初跑的是 sqlite 版脚本 | 执行 2.2 |

### 2.2 把 integer 改成 boolean（可选但推荐）

执行 `sql/fix_bool_to_boolean.sql`：

- 只转换**确实是 integer** 的列，已经是 boolean 的自动跳过
- `using (is_active = 1)` 负责把 0/1 转成 false/true，**数据不丢**
- 幂等，可重复执行
- 已通过 PostgreSQL 语法校验

> 不做这一步也能正常用：代码会运行时探测列的真实类型，自动适配。
> 但类型规范了以后，换别的客户端/工具不会再踩坑。

### 2.3 Reboot 让新代码生效

**关键**：push 完不等于生效，Streamlit Cloud 只在 Reboot 时拉新代码。

1. 打开应用 → 右下角 **Manage app**
2. 日志面板右上角三个按钮，点 **`Reboot`**

```
[Rerun]  [Reboot]  [Clear cache]
   ↑        ↑           ↑
 没用    点这个     只清缓存不拉代码
```

3. 等 30~90 秒，日志出现 `You can now view your Streamlit app` 即成功
4. 刷新页面 → 用 `admin` / `teacher2026` 登录

## 附：如果还是登录不了，按顺序排查

| 现象 | 检查点 |
|---|---|
| 仍提示"账号或密码错误" | Supabase → Table Editor → `teachers` 表，看 `username` 是否是 `admin`、`is_active` 是否 `true` |
| `teachers` 表是空的 | INSERT 没执行成功，换个账号名再试（比如 `admin2`），看是否报唯一冲突 |
| 报 `column "must_change_pwd" does not exist` | 表是旧版建的，缺字段。执行 `sql/schema_supabase.sql` 补齐（幂等） |
| 报 `boolean = integer` 类错误 | 表结构不匹配，跑 2.2 的规范化脚本 |
| 页面直接白屏/报 500 | Manage app 日志里找 `psycopg.errors.XXX`，对照 `documents/05_云端报错排查.md` |

## 附：以后新增账号的正确方式

**不要手写 INSERT**（哈希很容易算错）。两种稳妥办法：

1. **在应用里注册**：登录页 → 「没有账号？注册老师账号」（需 Secrets 里 `ALLOW_TEACHER_SIGNUP = "true"`）
2. **让班主任添加**：班级管理 → 科任老师 → 新建账号并加入（会同时设置任教科目）

只有确实需要在数据库里直接建号时，才用 `sql/create_admin.sql` 那样的模板，
并且哈希必须用 `core.security.hash_password()` 生成，不能从网上抄。
