# 国内低价部署方案（替代 Streamlit Cloud）

> 本次已把应用侧性能修好（连接池 + 缓存 + fastReruns）。但**跨洋链路延迟**是
> Streamlit Cloud 的固有成本：国内访问美国节点，单次 RTT 150~250ms，
> 首屏要下载几百 KB 的 JS/CSS，累计就是 3~8 秒。想真正快，必须把应用搬到国内。
>
> 本文给 4 个方案，按"便宜 + 简单"排序。

---

## 先看结论

| 方案 | 年成本 | 上手难度 | 国内速度 | 适合 |
|---|---|---|---|---|
| **A. 阿里云轻量 + Supabase** | ~¥96 | ⭐⭐ | 快（首屏<1.5s） | **推荐**：改动最小 |
| B. 阿里云轻量 + 自建 PostgreSQL | ~¥96 | ⭐⭐⭐ | 最快 | 想彻底掌控数据 |
| C. 腾讯云轻量 + Supabase | ~¥120 | ⭐⭐ | 快 | 已有腾讯云账号 |
| D. 保留 Streamlit Cloud + 国内 CDN 前置 | ~¥0 | ⭐⭐⭐⭐ | 一般 | 不想花钱但麻烦 |

**推荐 A**：数据库继续用 Supabase（免费额度够），只把 Streamlit 应用搬到国内服务器。
代码零改动，只改两个环境变量。

## 方案 A：阿里云轻量应用服务器 + Supabase（推荐）

### 成本明细

| 项 | 配置 | 价格 |
|---|---|---|
| 阿里云轻量应用服务器 | 2核2G / 40GB SSD / 3M带宽 | **新用户 ¥68~99/年**（常见活动） |
| 系统 | Ubuntu 22.04 | 免费 |
| 数据库 | Supabase 免费版 | ¥0 |
| 域名（可选） | .top / .cn | ¥9~30/年 |
| **合计** | | **约 ¥100/年** |

> 2核2G 跑 Streamlit + 几十个用户绰绰有余（内存占用约 300MB）。

### 步骤 1：买服务器（5 分钟）

1. 打开 https://www.aliyun.com/product/swas
2. 选 **轻量应用服务器** → 地域选**离你近的**（如华东1-杭州、华南1-深圳）
3. 镜像选 **系统镜像 → Ubuntu 22.04**
4. 套餐：2核2G / 3M带宽 / 40GB
5. 购买后到控制台 → **防火墙** → 放行端口 `8501`（应用）和 `22`（SSH）

### 步骤 2：连服务器装环境（10 分钟）

用 SSH 登录（阿里云控制台有"远程连接"按钮，不用装工具）：

```bash
# 1. 更新
sudo apt update && sudo apt install -y python3-pip python3-venv git nginx

# 2. 拉代码
cd /opt
sudo git clone https://github.com/xptcguan/class_eval.git
sudo chown -R $USER:$USER /opt/class_eval

# 3. 建虚拟环境装依赖（用国内镜像，快）
cd /opt/class_eval
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

### 步骤 3：配置环境变量（3 分钟）

```bash
cd /opt/class_eval
cp .env.example .env
nano .env
```

填成（数据库继续用你的 Supabase）：

```ini
APP_MODE=cloud
SUPABASE_URL=https://你的项目ref.supabase.co
SUPABASE_SERVICE_KEY=eyJhbGciOiJIUzI1NiIs...（service_role，完整 JWT）
DATABASE_URL=postgresql://postgres.项目ref:密码@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
SUPABASE_BUCKET=class-eval

ALLOW_TEACHER_SIGNUP=true
DEFAULT_ADMIN_USER=admin
DEFAULT_ADMIN_PASSWORD=你的密码
SHOW_RANK_DEFAULT=true
APP_SECRET_KEY=一长串随机字符
PLAY_CODE=0000
```

保存：`Ctrl+O` 回车，`Ctrl+X` 退出。

> ⚠️ Supabase 在**新加坡/东京**的话，国内到 Supabase 的延迟约 60~100ms，
> 比原来"国内→美国 Streamlit→美国 Supabase"的双跨洋好很多。

### 步骤 4：让应用开机自启（5 分钟）

创建 systemd 服务：

```bash
sudo nano /etc/systemd/system/xingguang.service
```

粘贴：

```ini
[Unit]
Description=星光评阅屋 (Streamlit)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/class_eval
Environment="PATH=/opt/class_eval/.venv/bin"
ExecStart=/opt/class_eval/.venv/bin/streamlit run app.py \
  --server.port 8501 \
  --server.address 127.0.0.1 \
  --server.headless true \
  --browser.gatherUsageStats false
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now xingguang
sudo systemctl status xingguang      # 看到 active (running) 就成功
```

### 步骤 5：加 Nginx 反向代理（必需，否则 WebSocket 会断）

Streamlit 依赖 WebSocket，必须走 Nginx 转发，否则页面上按钮点了没反应。

```bash
sudo nano /etc/nginx/sites-available/xingguang
```

```nginx
server {
    listen 80;
    server_name _;                 # 有域名就填域名

    location / {
        proxy_pass http://127.0.0.1:8501;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 86400;
        proxy_buffering off;
    }
}
```

启用：

```bash
sudo ln -s /etc/nginx/sites-available/xingguang /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

现在浏览器打开 `http://服务器公网IP` 就能用了。

### 步骤 6：加 HTTPS（可选，5 分钟）

有域名的话（家长用手机访问建议加，否则部分浏览器会提示不安全）：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名.com
# 按提示输入邮箱，选 2（自动跳转 HTTPS）
```

证书 90 天自动续期，不用管。

### 步骤 7：以后更新代码

```bash
cd /opt/class_eval
sudo systemctl stop xingguang
git pull
source .venv/bin/activate && pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
sudo systemctl start xingguang
```

比 Streamlit Cloud 的"Reboot"还快。

## 方案 B：国内服务器 + 自建 PostgreSQL

如果不想依赖 Supabase（或想彻底掌控数据）：

```bash
sudo apt install -y postgresql
sudo -u postgres psql
```

```sql
CREATE DATABASE class_eval;
CREATE USER ce_user WITH PASSWORD '强密码';
GRANT ALL PRIVILEGES ON DATABASE class_eval TO ce_user;
\q
```

然后执行建表脚本：

```bash
sudo -u postgres psql -d class_eval -f /opt/class_eval/sql/schema_supabase.sql
```

`.env` 改成：

```ini
APP_MODE=cloud
DATABASE_URL=postgresql://ce_user:强密码@127.0.0.1:5432/class_eval
```

**但图片存储还需要处理**：Supabase Storage 用不了时，把 `SUPABASE_BUCKET` 留空，
应用会自动退化为**本地目录存储**（`data/uploads/`），部署在服务器上完全够用。

> 这样连 Supabase 都不用了，年成本就是服务器 ¥96。

## 方案 D：不搬家，只加国内代理（省钱但有限）

如果暂时不想买服务器，可以在 Streamlit Cloud 前挡一层国内可访问的反向代理
（如 Cloudflare 中国网络、或国内小厂 CDN）。但：

- Cloudflare 免费版中国节点需要备案域名；
- Streamlit 的 WebSocket 在部分 CDN 上不稳定；
- 首屏 JS 仍要从美国拉，提速有限（可能从 8s 降到 4s）。

**不推荐**，除非只是想临时改善。

## 关于 403 `Invalid Compact JWS`

这个报错和部署位置无关，是 Supabase 密钥配置问题：

```
StorageApiError: {'statusCode': 403, 'error': 'Unauthorized', 'message': 'Invalid Compact JWS'}
```

意思是：Storage 服务拿到的 token **签名校验不通过**。三个原因按概率排序：

| 原因 | 怎么确认 | 怎么修 |
|---|---|---|
| `SUPABASE_SERVICE_KEY` 是从**别的项目**复制的 | 对比 URL 里的 ref 与 key 是否同一项目 | 到该项目 Settings → API Keys 重新复制 |
| 用的是 **anon key** 而不是 **service_role** | anon 也能是 JWT，但无 Storage 写权限 | 复制 `service_role` 那一行 |
| key 复制不完整（缺尾巴/多了空格） | 长度明显不对 | 点 Reveal 后完整复制，别手动截断 |

本次已在代码里加了**启动时校验**：如果 key 不以 `eyJ` 开头，会直接提示"不是 JWT，
请复制 service_role"，而不是等上传时才 403。

**验证方法**：登录后在「设置与导出」页点"测试图片存储"，会明确告诉你是 URL 错了还是 key 错了。
