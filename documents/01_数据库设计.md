# 数据库设计说明（SQLite / Supabase 双套建表 + Storage 配置）
> 建表脚本：
> - 本地 SQLite：`sql/schema_sqlite.sql`（应用首次启动会自动执行，无需手工跑）
> - 云端 Supabase：`sql/schema_supabase.sql`（需在 Supabase 控制台 SQL Editor 手工执行一次）

---

## 1. 全局设计约定

| 项目 | SQLite（local） | Supabase（cloud） | 说明 |
|---|---|---|---|
| 主键 | `TEXT` 存 UUID | `uuid default gen_random_uuid()` | 由应用生成（`core/security.new_id()`），两套通用 |
| 时间 | `TEXT`，`'YYYY-MM-DD HH:MM:SS'` 本地时间 | `timestamptz` | 榜单的今日/本周/本月边界在 Python 侧算好再传参，避免两端时区函数差异 |
| 布尔 | `INTEGER 0/1` | `boolean` | 写入时统一传 `int(bool)`，SQLite 直接存，Postgres 驱动会自动转 |
| 占位符 | `?` | `%(p0)s` | 业务 SQL 只写一套 `?`，`core/db._q()` 按模式改写 |
| 删除策略 | 软删除 | 软删除 | 学生 `is_active`、打分 `status='revoked'`、标签 `is_active`、班级 `is_archived`；不存在物理删除业务数据的入口 |

**为什么云端不直接用 PostgREST（`sb.table()`）？**

榜单/日志页需要 `LEFT JOIN + 条件聚合 + GROUP BY`，用 PostgREST 要拆成多次请求再在内存里拼，既慢又容易漏算（例如撤回后总分回滚）。所以云端统一走 **psycopg 直连 Supabase 的 Session Pooler**，一套 SQL 两端通用，页面代码零改动。

> 直连凭据（`DATABASE_URL`）与 `service_role` 密钥都只出现在服务器端 Secrets 里，浏览器永远拿不到。

## 2. 表结构总览（9 张表）

```
teachers ──┬── teacher_classes ──┬── classes ──┬── students      （学生档案）
           │   (多对多+角色)      │             ├── eval_tags     （评价标签）
           │                     │             ├── groups        （小组）
           │                     │             ├── score_logs    （打分流水·核心）
           │                     │             ├── class_settings（班级设置）
           │                     │             └── audit_logs    （审计日志）
           └── score_logs.recorded_by / revoked_by
```

### 2.1 teachers 教师账号
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT/uuid PK | |
| username | TEXT UNIQUE | 登录账号 |
| password_hash | TEXT | `pbkdf2_sha256$迭代$盐$摘要`，**绝不存明文** |
| display_name | TEXT | 显示姓名（打分记录里做快照） |
| role | TEXT | `head_teacher` / `subject_teacher`（账号级默认角色） |
| is_active | 0/1 / bool | 停用后无法登录 |
| must_change_pwd | 0/1 / bool | 1 = 首次登录强制改密码 |

> 注意：**权限的真正依据不是这个字段，而是 `teacher_classes.teacher_role`**。
> 同一个老师可能在 A 班是科任、在 B 班是班主任。

### 2.2 classes 班级
| 字段 | 说明 |
|---|---|
| id | |
| name | 例：八年级(3)班 |
| grade / school_year | 年级 / 学年（导出表头用） |
| head_teacher_id | 当前班主任（可移交） |
| created_by | 创建者 |
| is_archived | 归档标记，归档后家长/投屏列表不再出现，数据全留 |

### 2.3 teacher_classes 教师-班级关系（权限表）
| 字段 | 说明 |
|---|---|
| teacher_id / class_id | UNIQUE(teacher_id, class_id) |
| teacher_role | `head_teacher` / `subject_teacher` ← **权限判断唯一依据** |
| subject | 任教学科（科任老师） |

### 2.4 students 学生档案
| 字段 | 说明 |
|---|---|
| id / class_id | |
| student_no | 学号，班内 UNIQUE |
| name / gender / group_name | 姓名 / 性别 / 小组名 |
| avatar_key | 预设头像 key（`a01`~`a16`，程序化 SVG，见下） |
| avatar_url | 自定义头像（本地路径或 Supabase URL） |
| total_score | 冗余累计积分（列表排序用；权威值来自流水统计） |
| parent_code | **家长查看码**（4 位数字，班内唯一） |
| is_active | 移出班级=0（软删除） |

### 2.5 eval_tags 评价标签
| 字段 | 说明 |
|---|---|
| name / score | 名称 / 分值（正=加分项，负=扣分项，0 非法） |
| category | 由分值推导：加分项 / 扣分项 |
| icon | emoji |
| is_active | 0=停用（历史日志不受影响） |

### 2.6 groups 小组
`(class_id, name)` UNIQUE。小组批量打分按 `students.group_name` 匹配成员。

### 2.7 score_logs 评价流水（核心表，永久存档）
| 字段 | 说明 |
|---|---|
| class_id / student_id | 学生 |
| target_type | `student`（单人）/ `group`（小组批量，每名学生一条明细） |
| group_id | 来自哪个小组 |
| batch_id | **同一次批量打分共享**，用于"整批撤回" |
| tag_id / tag_name / score | tag_name、score 是**快照**：标签改名/停用后历史记录照样可读 |
| remark / image_url | 文字备注 / 图片凭证 |
| recorded_by / recorded_by_name | 打分老师（快照姓名） |
| status | `normal` / `revoked` ← **软删除** |
| revoked_by / revoked_at / revoke_reason | 撤回留痕 |

索引：`(class_id, created_at)`、`(student_id)`、`(batch_id)`。

### 2.8 audit_logs 审计日志
撤回、删标签、重置查看码、加老师等关键操作全部记一条，`/设置与导出 → 评价日志 → 审计日志` 可查。

### 2.9 class_settings 班级设置
目前只有 `show_rank`（榜单是否显示名次，防攀比），可扩展。

## 3. Supabase Storage 存储桶配置

### 3.1 创建桶
1. 控制台左侧 **Storage** → **New bucket**
2. Bucket name：`class-eval`（与 Secrets 中 `SUPABASE_BUCKET` 一致）
3. **Public bucket：勾选 ✅**
   - 勾选后图片 URL 形如 `https://<proj>.supabase.co/storage/v1/object/public/class-eval/score/20261122/xxx.jpg`，可直接放进 `<img src>`，家长端也能看。
   - 不勾选也可以，但需要改用 signed URL（会有过期问题，本项目未采用）。
4. File size limit 建议设 `5 MB`（与代码里 `MAX_UPLOAD_MB` 一致）
5. Allowed MIME types 建议只勾 `image/png, image/jpeg, image/webp`

等价 SQL（在 SQL Editor 执行也可）：
```sql
insert into storage.buckets (id, name, public)
values ('class-eval', 'class-eval', true)
on conflict (id) do nothing;
```

### 3.2 目录规划（代码自动创建）
```
class-eval/
├── avatars/20261122/<uuid>_头像.png      学生自定义头像
└── score/20261122/<uuid>_课堂表现.jpg    打分图片凭证
```
按日期分目录，方便以后按学期批量清理旧图片。

### 3.3 安全说明
- 桶虽然 public（可读），但 **对象名带 12 位随机 UUID**，无法枚举猜测。
- 上传/删除通过 `service_role` 在服务端完成，**浏览器端没有任何写权限**。
- 数据库层 `RLS` 全部开启且不给 `anon` 任何策略，即使有人拿到 anon key 也读不到成绩数据（见 `schema_supabase.sql` 第 9 节）。

## 4. 常用查询（业务口径）

```sql
-- 4.1 榜单：按周期汇总净积分（同分并列在应用层用竞争排名处理）
SELECT s.id, s.name, s.student_no, s.group_name, s.total_score,
       COALESCE(SUM(CASE WHEN l.status='normal' THEN l.score ELSE 0 END),0) AS period_score,
       COALESCE(SUM(CASE WHEN l.status='normal' AND l.score>0 THEN l.score ELSE 0 END),0) AS plus_sum,
       COALESCE(SUM(CASE WHEN l.status='normal' AND l.score<0 THEN l.score ELSE 0 END),0) AS minus_sum
FROM students s
LEFT JOIN score_logs l ON l.student_id = s.id
     AND l.created_at >= ? AND l.created_at < ?
WHERE s.class_id = ? AND s.is_active = 1
GROUP BY s.id, s.name, s.student_no, s.group_name, s.total_score
ORDER BY period_score DESC;

-- 4.2 撤回：软删除 + 回滚总分（同一事务）
UPDATE score_logs SET status='revoked', revoked_by=?, revoked_at=?, revoke_reason=?
WHERE id=? AND status='normal';
UPDATE students SET total_score = total_score - ? WHERE id=?;

-- 4.3 家长只能看自己孩子
SELECT * FROM score_logs
WHERE student_id = ? AND status='normal'
ORDER BY created_at DESC;
```

## 5. 预设头像（规避版权）

`core/avatars.py` 用 **SVG 现场绘制** 16 款"Q 版校园风"头像：
大头小身比例、粗描边、马卡龙配色、校服领 + 发卡/眼镜等配饰。
**不包含任何第三方素材**，无版权风险，可随意使用。

老师也可以给学生上传真实照片/自绘头像，`avatar_url` 优先于 `avatar_key` 展示。
