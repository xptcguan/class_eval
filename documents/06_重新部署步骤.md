## 二、判断要不要 Redeploy 还是只要 Reboot

这决定你点哪个按钮，别点错。

| 你这次改了什么 | 需要点的按钮 |
|---|---|
| 只改了 `.py` 代码（**本次属于这种情况**） | **Reboot** 就够 |
| 改了 `requirements.txt`（新增/删依赖） | **Reboot**（会重装依赖） |
| 改了 `runtime.txt`（Python 版本） | **Redeploy** |
| 改了 `.streamlit/config.toml` | **Reboot** |
| 想让构建缓存彻底清掉、怀疑装错了 | **Redeploy** |

本次只改了 `core/db.py` + 新增两个文件，**Reboot 即可，1 分钟搞定**。

## 三、操作步骤（Reboot 路线，推荐）

### 3.1 打开应用管理后台
1. 浏览器打开你的应用地址（形如 `https://xxx.streamlit.app`）
2. 如果页面显示报错，右下角有 **Manage app**，点它
3. 如果页面正常，点右上角 **⋮** → **Manage app**
4. 右侧会滑出日志面板

### 3.2 执行 Reboot
在日志面板右上角，有三个按钮：

```
[Rerun]  [Reboot]  [Clear cache]
```

点 **Reboot**（**不是** Rerun）。

- `Rerun` = 重新执行当前跑着的旧代码，**没用**
- `Reboot` = 重新拉代码 + 重启进程，**这才是你要的**
- `Clear cache` = 只清 `@st.cache_resource`，不拉新代码

### 3.3 等待重启
界面上会出现 `Rebooting...`，约 **30~90 秒**。
日志里会看到：

```
Cloning https://github.com/xptcguan/class_eval ...
...
You can now view your Streamlit app
```

看到这行就说明新代码起来了。

### 3.4 验证修复生效
1. 刷新页面
2. 用 `admin` + 你的密码登录
3. **能进入首页不报错** = 布尔问题已解决

如果还报错，跳到第五节。

## 四、如果 Reboot 后仍是旧代码 / 想彻底重建（Redeploy 路线）

有些情况 Reboot 拉不到新提交（GitHub webhook 抖动、构建缓存异常）。这时走完整重建：

### 4.1 本地推送命令（备查）

```bash
cd class_eval

# 看当前状态：应显示 main...origin/main 且无待提交项
git status -sb

# 若仍有未提交改动，按需提交（本次已提交，可跳过）
git add -A
git commit -m "描述你的改动"

# 推送
git push origin main
```

**推送前自查**（很重要，避免把密钥传上去）：

```bash
# 下面两条都应无输出
git status --porcelain | grep -i "\.env"
git ls-files | grep -E "\.env$|\.db$|secrets\.toml$"
```

### 4.2 Streamlit Cloud 上重建

1. 打开 https://share.streamlit.io
2. 找到你的 app → 右上 **⋮** → **Settings**
3. 切到 **General** 标签，最下方有 **Delete app**（先别点！）
4. 更稳的做法：**直接在应用页点 Reboot**，若无效再考虑删除重建

如果要重建，注意 **Deploy 时 Secrets 不会自动保留**（删 app 会丢 Secrets），
重建前先把 Secrets 全文复制到记事本。

### 4.3 新建应用（仅在必须删旧应用时）

1. **Create app** → **Deploy a public app from GitHub**
2. Repository：`xptcguan/class_eval`
3. Branch：`main`
4. **Main file path：`app.py`** ← 注意不是 `Home.py`
5. **Advanced settings → Secrets**：粘贴第六节的完整配置
6. Deploy

## 五、Reboot 之后还报错的排查顺序

### 5.1 先看异常类型，别猜

日志面板最底部那几行是真实错误，形如：

```

```

按类型对照 `documents/05_云端报错排查.md`。

### 5.2 确认新代码真的跑起来了

日志里搜不到你的新提交？说明没拉到。检查：

```bash
# 本地确认远程是这个提交
git ls-remote origin main
# 应输出 3381b33... refs/heads/main
```

### 5.3 本次修复对应的验证点

| 现象 | 说明 |
|---|---|
| 登录时报 `boolean = integer` | 说明还在跑旧代码 → 再 Reboot 一次，确认点击的是 Reboot |
| 登录成功、能看到仪表盘 | ✅ 修复生效 |
| 报 `relation "xxx" does not exist` | 是另一类问题（表没建），去 Supabase 执行 `schema_supabase.sql` |
| 报连接超时 | `DATABASE_URL` 用了 Direct connection，换 Session pooler |

## 六、Secrets 完整模板（重建应用时用）

在 **Advanced settings → Secrets** 里粘贴，注意 TOML 格式、值用双引号：

```toml
APP_MODE = "cloud"

SUPABASE_URL = "https://你的项目ref.supabase.co"
SUPABASE_SERVICE_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.xxxxx"
DATABASE_URL = "postgresql://postgres.你的项目ref:数据库密码@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres"
SUPABASE_BUCKET = "class-eval"

ALLOW_TEACHER_SIGNUP = "true"
DEFAULT_ADMIN_USER = "admin"
DEFAULT_ADMIN_PASSWORD = "你的强密码"
SHOW_RANK_DEFAULT = "true"
APP_SECRET_KEY = "一长串随机字符至少32位"
PLAY_CODE = "8888"
```

三个容易错的地方：

1. `DATABASE_URL` 必须是 **Session pooler**（`...pooler.supabase.com:5432`），
   不是 `db.xxx.supabase.co:5432` 的 Direct connection
2. 数据库密码含 `@ : / ? #` 要做 URL 编码（`@` → `%40`）
3. 改完 Secrets **必须 Reboot** 才生效

## 七、上线后的功能验收清单

Reboot 成功后按顺序走一遍，确认不只是"能打开"：

| # | 检查 | 预期 |
|---|---|---|
| 1 | admin 登录 | 进入快速评分页，看到仪表盘卡 |
| 2 | 侧边栏点「班级管理」 | 能看到「新建班级」表单（之前这里进不去） |
| 3 | 建一个测试班 → 录 2 个学生 | 学生卡片出现 |
| 4 | 点学生名字打一次分 | 分数变化 + 有轻提示 |
| 5 | 打开「积分榜单」 | 卡片有分数、组内名次，前三名有奖牌 |
| 6 | 榜单页快速连点 今日/本周/本月/总榜 | 不报错、不乱 |
| 7 | 打开「投屏榜单」切「小组榜」 | 只显示小组名，无学生姓名 |
| 8 | 上传一张图片凭证 | Supabase Storage 桶里能看到该文件 |
| 9 | 家长端用学号+查看码登录 | 只看得到自己孩子，无撤回按钮 |
| 10 | 关掉浏览器 20 分钟后再进 | **数据还在**（证明不是写本地 SQLite） |

第 10 项最关键：如果重启后数据没了，说明 `APP_MODE` 不是 `cloud`。

## 八、以后改代码的标准流程

```bash
# 1. 本地改代码
# 2. 本地先自测
python tools/check_sql.py          # 改了 SQL 必跑
python tests/test_app_smoke.py     # 改了页面必跑

# 3. 提交并推送
git add -A
git commit -m "feat: 描述"
git push origin main

# 4. 回到 Streamlit → Manage app → Reboot
# 5. 刷新页面验证
```

养成第 2 步的习惯，能避免"本地正常、云端报错"再来一轮。
