# 云端报错排查速查（Streamlit Cloud + Supabase）

> 部署后页面报 `This app has encountered an error` 时，先看**最上面那行异常类型**，  
> 然后在下面按类型找到对应原因。完整的原始错误在：应用右下角 **Manage app** → 日志。

---

## 一、按异常类型定位

### 1. `psycopg.errors.UndefinedFunction`（最常见）

**含义**：Postgres 说"不认识这个东西"。它有两种完全不同的原因，
**先看有没有 `HINT: operator does not exist` 这一行来区分**。

#### 1-A. 带 `operator does not exist: boolean = integer`

```
psycopg.errors.UndefinedFunction: operator does not exist: boolean = integer
LINE 1: ...WHERE lower(username) = lower($1) AND is_active = 1
HINT:  No operator matches the given name and argument types. You might need to
       add explicit type casts.
```

这是**布尔列写了 `= 0 / = 1`**。SQLite 是 `INTEGER 0/1` 能这么写，
Postgres 的 `boolean` 只认 `true / false`，且不做隐式转换。

**本项目的处理（已修好，不需要你改表）**：
`core/db.py` 里的 `_bool_safe()` 在执行前统一改写：
`is_active = 1` → `is_active = true`，`is_archived = 0` → `is_archived = false`。
SQLite 与 Postgres 两条路径都走这个改写（SQLite 3.23+ 同样支持 `true/false` 字面量），
所以**一份 SQL 两边都能跑**，不用维护两套。

覆盖的布尔列：`is_active`、`is_archived`、`show_rank`、`must_change_pwd`。

自检：
```bash
python tools/check_sql.py
# 会单独打印「布尔列写法检查」小节，并校验改写后的 SQL 在 PG 语法下是否合法
```

**如果你自己新加了 SQL 仍报这个错**：要么把它改成 `= true / = false`，
要么把新列名加进 `core/db.py` 的 `_BOOL_COLUMNS` 元组。

#### 1-B. 不带 operator 提示，只说 `function xxx does not exist`

这才是"表/函数不存在"，按下面排查：

| 可能原因 | 怎么确认 | 怎么修 |
|---|---|---|
| **没执行 `sql/schema_supabase.sql`** | Supabase → Table Editor 看不到 9 张表 | 到 SQL Editor 全文执行一次 |
| **只执行了一部分** | 表少于 9 张 | 重新全文执行（幂等，可安全重复） |
| **连错了项目** | 连接串里的项目 ref 与浏览器打开的浏览器项目不一致 | 换成同项目的 Session pooler 串 |

**修复后检查**：重新打开应用 → 用 admin 登录 → 能进登录页（说明 `classes` 表可读）。

---


### 1-C. `operator does not exist: integer = boolean`（反向报错）

```
RuntimeError: 数据库缺少表或函数...
原始错误：operator does not exist: integer = boolean
LINE 1: SELECT id, name FROM classes WHERE is_archived = false ORDER...
```

**这是 1-A 的镜像**：库里 `is_archived` 是 **integer**，而 SQL 里写的是 `false`。

**根因**：在 Supabase SQL Editor 里执行的是 `sql/schema_sqlite.sql`（SQLite 版），
而不是 `sql/schema_supabase.sql`（Postgres 版）。前者布尔列是 `INTEGER`。

**两条路，任选其一：**

**路线 A（推荐，规范化）：把列改成真正的 boolean**
到 Supabase → SQL Editor 执行 `sql/fix_bool_to_boolean.sql`：
- 只转换确实是 integer 的列，已经是 boolean 的自动跳过
- 幂等，可重复执行
- 1 → true、其余 → false，数据不丢
- 执行完回 Streamlit → **Reboot**（程序会重新探测列类型）

**路线 B（不推荐，但能用）：不做任何操作**
本项目的 `core/db.py` 会**运行时探测列的真实类型**，
是 boolean 就写 `true/false`，是 integer 就写 `0/1`，
所以即使表结构不规范也能跑。但类型不规范以后换别的工具/客户端容易再踩坑。

**怎么确认自己库里的真实类型**：
```sql
select table_name, column_name, data_type
from information_schema.columns
where table_schema='public'
  and column_name in ('is_active','is_archived','show_rank','must_change_pwd')
order by table_name;
```
`data_type` 是 `integer` 就是 SQLite 版建的表，是 `boolean` 就是正确版本。

### 1-D. 其他布尔相关报错

| 报错 | 原因 | 修法 |
|---|---|---|
| `column "is_active" is of type boolean but expression is of type integer` | `INSERT/UPDATE` 把 0/1 写进布尔列 | 传 Python 的 `True/False`，不要传 `0/1` |
| `COALESCE(show_rank, 0)` 类型冲突 | 默认值类型与列类型不一致 | 改成 `COALESCE(show_rank, false)` |

### 2. `psycopg.OperationalError` / `connection ... failed` / `Network is unreachable`

**含义**：连不上数据库。

| 原因                                                                   | 修法                                                             |
| -------------------------------------------------------------------- | -------------------------------------------------------------- |
| `DATABASE_URL` 用了 **Direct connection**（只有 IPv6，Streamlit Cloud 连不上） | 换成 **Session pooler** 连接串（Supabase → Connect → Session pooler） |
| 数据库密码含 `@ : / ? #` 没编码                                               | `@` → `%40`，或到 Supabase 重置成纯字母数字密码                             |
| `DATABASE_URL` 末尾缺 `/postgres`                                       | 补上                                                             |
| Supabase 项目被暂停（免费版 7 天无活动会 pause）                                    | Supabase 控制台点 Restore                                          |

---

### 3. `psycopg.errors.InvalidPassword` / `password authentication failed`

数据库密码填错。到 Supabase → Project Settings → Database → Reset database password，  
然后把新的密码同步到 `DATABASE_URL`（记得 URL 编码）。

---

### 4. `RuntimeError: 云端模式缺少 DATABASE_URL`

Secrets 里没配 `DATABASE_URL`，或键名拼错。注意 Secrets 是 **TOML 格式**：

```toml
APP_MODE = "cloud"
DATABASE_URL = "postgresql://postgres.xxxx:密码@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres"
```

值必须用**双引号**包起来。

---

### 5. `ModuleNotFoundError: No module named 'psycopg'` / `'supabase'`

`requirements.txt` 里缺依赖。本项目已包含：

```
supabase>=2.5.0
psycopg[binary]>=3.1
```

改完 `requirements.txt` 后，到 **Manage app → Reboot**（不是 Refresh）才会重新装依赖。

---

### 6. `Error installing requirements`（构建阶段失败）

| 原因                             | 修法                                         |
| ------------------------------ | ------------------------------------------ |
| `psycopg[binary]` 装不上          | 确认写的是 `psycopg[binary]`，不是 `psycopg` 裸包    |
| `runtime.txt` 指定的 Python 版本不支持 | 本项目写的是 `python-3.11`，是支持的版本                |
| 依赖版本冲突                         | 把 `requirements.txt` 里的 `>=` 收紧或放宽后 Reboot |

---

### 7. `StreamlitPageNotFoundError: Could not find page: pages/xxx.py`

页面没在 `app.py` 里注册。所有页面（含 `pages/7_parent_view.py`）都必须在  
`st.navigation(pages)` 的字典里出现过一次，否则 `st.switch_page` 找不到。

---

### 8. 页面能打开但图片 404 / 403

| 原因                                         | 修法                                                   |
| ------------------------------------------ | ---------------------------------------------------- |
| Storage 桶不是 Public                         | Supabase → Storage → 桶 → Settings → 改 Public         |
| 桶名不一致                                      | 桶名必须等于 Secrets 里的 `SUPABASE_BUCKET`（默认 `class-eval`） |
| `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` 填错 | 用 `tools/check_env.py --cloud` 在本地验证                 |



---

### 9. 重启后数据全没了

`APP_MODE` 还是 `local`（SQLite 写在容器里，重启即丢）。  
Secrets 里必须是 `APP_MODE = "cloud"`。

---

## 二、本地先自查（比在云端反复试快得多）

```bash
# 1) 环境与建表
python tools/check_env.py                 # 本地 SQLite
python tools/check_env.py --cloud         # 按云端配置检查（会读 .env 里的 Supabase 参数）

# 2) SQL 在 Postgres 语法下是否合法（不需要连数据库）
python tools/check_sql.py

# 3) 页面渲染是否正常
python tests/test_app_smoke.py
```

`tools/check_sql.py` 会把本地跑过的**每一条 SQL** 都过一遍 PostgreSQL 官方语法解析器，  
提前发现"SQLite 能跑、Postgres 不认"的语句。

---

## 三、拿到完整报错的方法

Streamlit Cloud 的报错页会把细节**打码**，完整堆栈在两个地方：

1. 应用页面右下角 **Manage app** → 右侧出现日志面板 → 看最底部红色部分
2. Settings → **Secrets** 旁边有 **View app logs**

把完整的 `Traceback` 最后 5 行（含异常类型与 message）发出来，就能精确定位。
